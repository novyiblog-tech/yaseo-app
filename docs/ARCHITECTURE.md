# Архитектура: как сервис стоит на движке

Сергей, 30.09.2026: «давай уже будем двигаться по плану разработки».

Движок `yaseo` разобран по тегу v0.1.4 (github.com/novyiblog-tech/yaseo). Сигнатуры
`audit_site`, `readiness.check`, `build_plan`, `net.check_url` сверены на установленном пакете.

## 1. Что умеет движок и чего в нём нет

| свойство | состояние | что делаем |
|---|---|---|
| зависимости | ноль, только стандартная библиотека | ставим пакетом с тега, `pyproject.toml` |
| выдача Яндекса | только отложенные запросы, синхронных нет | совпадает с планом: всё фоном |
| Wordstat | частотность, топ, ассоциации одним вызовом | динамики и регионов отдельным вызовом нет — доработка движка |
| техаудит | 24 вида находок, у каждой цитата-доказательство | берём как есть |
| готовность к ИИ-поиску | robots.txt для ИИ-ботов, llms.txt, JSON-LD | берём как есть, бесплатно |
| ответы нейросетей | Яндекс, Perplexity, OpenAI, Gemini, Anthropic | связки «YandexGPT + Web Search» нет — доработка движка |
| защита от SSRF | есть, внутренние адреса закрыты по умолчанию | берём как есть |
| код | синхронный, без очереди и ограничителя скорости | очередь и ограничитель — в нашем слое |
| база, ключи, настройки | общие на процесс, в таблицах нет пользователя | один аудит — один процесс со своим каталогом |
| журнал расхода | нет, есть только смета до вызова | свой журнал обёрткой над платными вызовами |
| свой HTTP-клиент | подставить нельзя | учёт расхода ведём по числу вызовов, а не перехватом трафика |
| MCP и CLI | отдают текст | зовём функции Python, текст не разбираем |

## 2. Решения

1. **Один аудит — один процесс.** Исполнитель запускается с собственными `YASEO_DB`,
   `XDG_DATA_HOME`, `XDG_CONFIG_HOME`. Данные пользователей не пересекаются, движок
   править не нужно. Цена — запуск процесса на задачу, для фоновых аудитов приемлемо.
2. **Домен передаётся явно всегда.** «Единственный проект в базе» движка не используем.
3. **Ключи поставщиков в бесплатный аудит не попадают.** Исполнитель получает окружение
   без них. Платный исполнитель получит ключи отдельным словарём.
4. **Свои данные — в Postgres, база движка временная.** SQLite движка живёт, пока идёт
   задача; результат забирается в JSON и кладётся в нашу базу с пользователем и сайтом.
5. **Правки движка — в его репозиторий**, сюда только подъём тега (ADR-0011 в white-label).

| бесплатный аудит в отдельном процессе | `src/yaseo_app/free_audit.py` | 7 тестов |
| тестовый сайт с заведомыми дефектами | `tests/site/` | битая ссылка, два h1, нет description |

| оценка сайта: число, три светофора, шаги | `src/yaseo_app/score.py` | 8 тестов |
| дизайн-система: токены двух тем | `src/yaseo_app/design/tokens.css` | лайм, тёмная тема кабинета, светлая кремовая отчёта |

Оценка считается так: критическая находка весит 10, серьёзная 3, мелкая 1. Техника —
штраф делится на число страниц, 10 на страницу означает ноль. Нейросети — штраф на сайт,
25 означает ноль. Зелёный от 80, жёлтый от 50. Светофор Яндекса в бесплатной проверке
серый и в общее число не входит. Шаги «что сделать первым» — группы одинаковых находок,
сначала критические, внутри — по суммарному весу.

Проверка на тестовом сайте: техника 0 (одна критическая, семь серьёзных, десять мелких на
трёх страницах), нейросети 56, общая 24. Первый шаг — «Ссылка в никуда», 5 минут.

```bash
uv run python -m unittest discover -s tests -v
```

## 6. Этап 2 — ядро: очередь, журнал расхода, лимиты, кэш (30.09.2026)

Всё на Postgres, без отдельного брокера. Схема — `src/yaseo_app/schema.sql`, накатывается
исполнителем при старте.

| часть | файл | как устроено |
|---|---|---|
| очередь | `jobs.py` | `FOR UPDATE SKIP LOCKED`, аренда 20 мин; упавший исполнитель — задачу берёт другой; 3 попытки с паузой 30 с × 2ⁿ |
| журнал расхода | `ledger.py`, таблица `spend` | строка на каждое обращение, пишется ДО вызова под блокировкой источника; неудачный вызов остаётся с ценой |
| лимиты | `ledger.py` | все считаются из журнала: лимит пользователя в сутки (МСК), потолок сервиса в рублях в сутки, квота в час (Wordstat 100) |
| выключатели | таблица `sources` | включён, тарифы, цена, лимиты, срок кэша — будущая админка |
| кэш | таблица `cache` | Wordstat 30 дней, выдача 1 день, ответ нейросети 7 дней; попадание — строка в журнале с ценой 0 |
| источники | `sources.py` | живые (движок с ключами словарём) и виртуальные (выдуманные данные той же формы) |
| конвейер | `pipeline.py` | бесплатный аудит → Wordstat → выдача → нейросеть |
| исполнитель | `worker.py` | `python -m yaseo_app.worker [--once] [--sources fake\|live]` |

Поведение на отказах:
- сайт не открылся — задача падает до первой платной строки, денег не тратит;
- источник выключен, не в тарифе, лимит пользователя или потолок сервиса — раздел
  `skipped` или `partial` с причиной, отчёт собирается без него;
- квота Wordstat в час — задача откладывается без траты попытки, при повторе купленное
  берётся из кэша;
- поставщик отказал 3 раза подряд — раздел останавливается (скорее всего ключ).

Виртуальный режим (`YASEO_SOURCES=fake`, по умолчанию): конвейер, лимиты и журнал
проверяются на тестовом сайте без ключей. Расход пишется с пометкой `fake` и в живые
лимиты не входит; результат несёт `sources_mode: fake`.

```bash
uv run python scripts/demo_pipeline.py
```

Прогон 30.09.2026 на тестовом сайте, 4 запроса: 20,52 ₽ виртуального расхода, из них
20,32 ₽ — генеративный ответ Яндекса (5,08 ₽ за запрос). Второй прогон — 0 ₽, всё из кэша.
Тестов 50, из них новых 26 (очередь 7, журнал 12, конвейер 7).

Не сделано в этапе 2: отчёт пока рисует только бесплатные разделы — платные подключаются
в шаге 7 этапа 1, форма данных для них теперь есть (`result.paid`).

## 7. Этап 3 — кабинет (30.09.2026)

Решение: кабинет рисуется на сервере — FastAPI и шаблоны Jinja, тёмная тема из тех же
токенов, что и отчёт. Next.js остаётся для лендинга (этап 6): для пяти экранов кабинета
второй язык и вторая сборка не окупаются. Логика — в `accounts.py`, страницы в `web.py`
только зовут её, поэтому переезд фронта ничего не ломает.

| экран | адрес | что делает |
|---|---|---|
| регистрация | `/signup` | почта, пароль от 10 знаков, согласие на обработку ПДн (время согласия в базе) |
| вход | `/login` | 8 неудачных попыток за 15 минут — вход по этой почте закрыт на 15 минут |
| сайты | `/sites` | список, добавить адрес; внутренние адреса отклоняются (защита от SSRF движка) |
| сайт | `/sites/{id}` | запуск проверки с запросами, история и расход каждой проверки |
| проверка | `/jobs/{id}` | пока идёт — страница обновляется сама; готово — оценка, шаги, платные разделы |
| отчёт | `/jobs/{id}/report` | полный отчёт в светлой теме, тот же, что уходит в PDF |

Безопасность: пароль — scrypt; в cookie случайный токен, в базе только его хэш; cookie
HttpOnly, Secure, SameSite=Lax; CSRF-токен в каждой форме; CSP без внешних скриптов;
чужой сайт и чужая проверка отдают 404, как несуществующие. Ограничения: 20 сайтов,
3 проверки одновременно, одна на сайт, до 50 страниц обхода.

Запуск на машине разработчика, без ключей и трат — тестовый сайт, исполнитель и веб разом:

```bash
scripts/dev.sh
```

Кабинет на http://127.0.0.1:8000, тестовый сайт для проверки — `http://127.0.0.1:8765/`.
Проверено 30.09.2026 в браузере: регистрация, добавление сайта, проверка с тремя
запросами, результат на ширине 1280 и 375. Тестов 62, из них 12 на кабинет.

Не сделано, нужно до приёма денег (этап 4):
- подтверждение почты и восстановление пароля — нужен сервис отправки писем;
- светофор «Яндекс» в оценке пока серый: позиции собираются, но в число не входят —
  подключается вместе с платными разделами отчёта;
- PDF отчёта из кабинета — рендер Chrome на сервере;
- текст согласия и политика обработки ПДн — от юриста, сейчас одна строка.

## 8. Этап 4 — деньги, история, «Мои сайты» (30.09.2026)

Тарифы — таблица `plans`, не код: цены и лимиты правятся без выкладки. Засеяна версия 2 из
PLAN.md §4, это гипотеза до решения владельцев. Лимиты тарифа: сайты, проверок за 30 дней,
запросов в проверке, проверок в нейросетях, сколько шагов открыто, PDF. Проверки в нейросетях
считаются по журналу расхода — ровно то, за что сервис заплатил Яндексу.

| часть | файл | как устроено |
|---|---|---|
| тариф и лимиты | `billing.py` | действующий тариф из подписки; истекла — бесплатный; лимиты уходят в параметры задачи |
| оплата | `billing.py`, `/billing` | платёж создаётся у нас, потом у сервиса; статус — только запросом к сервису |
| уведомления | `/pay/webhook/{сервис}` | из тела берётся только номер платежа; повтор не продлевает второй раз |
| продление | `python -m yaseo_app.billing renew` | раз в час из планировщика; не списалось — повтор раз в сутки, 3 дня льготы, потом бесплатный |
| виртуальная оплата | `FakeProvider`, `/pay/fake/{id}` | оплатить, отказаться, «карта не спишется при продлении» |
| PDF | `/jobs/{id}/report.pdf` | рендер Chrome на сервере, в платных тарифах |
| мои сайты | `/sites` | плитка: последняя оценка, изменение, график оценок, три светофора |
| история | `/sites/{id}` | оценка и число запросов у каждой проверки, удалить сайт |
| сравнение | `history.py`, `/jobs/{id}` | исправлено, появилось, осталось — по паре «находка + страница»; сдвиги позиций |

Бесплатный тариф: одна проверка в 30 дней, до 5 запросов, без нейросетей, открыты 3 шага.

Проверено 30.09.2026 в браузере: покупка «Про» через виртуальную оплату, проверка с четырьмя
запросами, сравнение с прошлой, PDF 470 КБ, плитка «Мои сайты». Тестов 80, из них 18 новых.

Чтобы подключить настоящую оплату, нужно от владельцев:
- ИП, на которое идут деньги, и магазин в ЮKassa или CloudPayments;
- чеки по 54-ФЗ — у сервиса оплаты, нужны ставка НДС и система налогообложения ИП;
- включённые у сервиса автоплатежи — для ЮKassa их включает менеджер по заявке;
- оферта и политика обработки ПДн на сайте — от юриста.
Код ЮKassa пишется одним классом по интерфейсу `Provider`, когда будет тестовый магазин.

Не сделано: пересчёт остатка при смене тарифа посреди периода (новый период с минуты оплаты),
«запросы под наблюдением» и свой логотип в отчёте — помечены в тарифах «скоро».

## 9. Проверки «что видит робот» и HTTPS (30.09.2026)

`site_checks.py`, идут в процессе бесплатного аудита, находки — в общий список движка,
поэтому оценка, шаги, отчёт и сравнение проверок их видят без отдельной логики.

| проверка | как | находка |
|---|---|---|
| заглушка защиты | главная роботом и браузером; метки Cloudflare, DDoS-Guard, Qrator, Servicepipe, Variti, SmartCaptcha, капч; коды 403/429/503 роботу | `bot-stub`, критическая; оценка не выставляется — находки по страницам были бы про заглушку |
| урезанная версия | браузеру текста в 3 раза больше, чем роботу | `bot-content-differs` |
| страница на скриптах | меньше 40 слов и есть скрипты | `js-only-page` |
| сертификат | цепочка и имя проверяются, срок | `no-https`, `tls-invalid`, `tls-expiring` (≤14 дней — серьёзная, ≤30 — мелкая) |
| адреса-копии | http и https, с www и без должны сойтись в один | `site-mirrors`, `http-not-redirected`, `redirect-temporary` (только между адресами, не внутри сайта) |

Сверено 30.09.2026 на ya.ru, python.org, habr.com — ложных находок нет; два ложных
срабатывания пойманы и закрыты тестами (короткая страница без скриптов, переход `/ → /ru/`).
Положительный контроль заглушки — живой сервер в тесте, роботу 503 с меткой Cloudflare.

## 10. Этап 5 — наблюдение (30.09.2026)

| часть | файл | как устроено |
|---|---|---|
| запросы под наблюдением | `monitor.py`, страница сайта | лимит по тарифу на весь кабинет; упал тариф — снимаются первые N, остальные ждут |
| съём позиций | задача `positions` | одна на сайт в день (ключ от повтора), первая десятка, кэш выдачи 20 часов |
| история | таблица `positions` | место за день по Москве; на странице — место, сдвиг за неделю, график за 30 дней |
| письмо недели | `digest.py`, `templates/email/` | сдвиги позиций, новые проверки, сертификат на исходе; нечего сказать — письма нет |
| очередь писем | `mailer.py`, таблица `outbox` | ключ от повтора, 5 попыток; SMTP по `YASEO_SMTP_*`, без него — файлы в `build/outbox` |
| отписка | `/unsubscribe`, `/settings` | ссылка подписана ключом `YASEO_SECRET`, работает без входа; заголовок `List-Unsubscribe` |
| планировщик | `python -m yaseo_app.scheduler` | с 03:00 МСК позиции, понедельник с 09:00 письма, каждую минуту почта и продления |

Машина разработчика: `scripts/dev.sh` поднимает и планировщик; письма смотреть на
`/dev/outbox`; `scripts/demo_week.py` дорисовывает две недели выдуманных позиций и
собирает письмо недели. Проверено в браузере: 5 запросов, съём, таблица с графиками, письмо.
Тестов 102.

Нужно до запуска писем:
- сервис отправки (Unisender, SendPulse, Яндекс 360 для домена) и домен с SPF, DKIM, DMARC;
- подтверждение почты при регистрации — иначе письма уйдут на чужие адреса,
  введённые с ошибкой или нарочно;
- `YASEO_SECRET` на сервере — без него ссылки отписки подписываются ключом из файла.

Не сделано: в журнале цена выдачи дневная (0,0305 ₽), ночной тариф 0,0254 ₽ не различается;
отписка в один клик по RFC 8058 (POST) — сейчас ссылка GET.
