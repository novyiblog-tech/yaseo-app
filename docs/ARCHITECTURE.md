# Архитектура: как сервис стоит на движке

Сергей, 30.09.2026: «давай уже будем двигаться по плану разработки».

Движок `yaseo` разобран по тегу v0.1.4 (github.com/novyiblog-tech/yaseo). Сигнатуры
`audit_site`, `readiness.check`, `build_plan`, `net.check_url` сверены на установленном пакете.

## 1. Что умеет движок и чего в нём нет

| свойство | состояние | что делаем |
|---|---|---|
| зависимости | ноль, только стандартная библиотека | ставим пакетом с тега, `pyproject.toml` |
| выдача Яндекса | только отложенные запросы, синхронных нет | совпадает с планом: всё фоном |
| Wordstat | частотность, топ, ассоциации одним вызовом | динамики и регионов отдельным вызовом нет — доработка движка |
| техаудит | 24 вида находок, у каждой цитата-доказательство | берём как есть |
| готовность к ИИ-поиску | robots.txt для ИИ-ботов, llms.txt, JSON-LD | берём как есть, бесплатно |
| ответы нейросетей | Яндекс, Perplexity, OpenAI, Gemini, Anthropic | связки «YandexGPT + Web Search» нет — доработка движка |
| защита от SSRF | есть, внутренние адреса закрыты по умолчанию | берём как есть |
| код | синхронный, без очереди и ограничителя скорости | очередь и ограничитель — в нашем слое |
| база, ключи, настройки | общие на процесс, в таблицах нет пользователя | один аудит — один процесс со своим каталогом |
| журнал расхода | нет, есть только смета до вызова | свой журнал обёрткой над платными вызовами |
| свой HTTP-клиент | подставить нельзя | учёт расхода ведём по числу вызовов, а не перехватом трафика |
| MCP и CLI | отдают текст | зовём функции Python, текст не разбираем |

## 2. Решения

1. **Один аудит — один процесс.** Исполнитель запускается с собственными `YASEO_DB`,
   `XDG_DATA_HOME`, `XDG_CONFIG_HOME`. Данные пользователей не пересекаются, движок
   править не нужно. Цена — запуск процесса на задачу, для фоновых аудитов приемлемо.
2. **Домен передаётся явно всегда.** «Единственный проект в базе» движка не используем.
3. **Ключи поставщиков в бесплатный аудит не попадают.** Исполнитель получает окружение
   без них. Платный исполнитель получит ключи отдельным словарём.
4. **Свои данные — в Postgres, база движка временная.** SQLite движка живёт, пока идёт
   задача; результат забирается в JSON и кладётся в нашу базу с пользователем и сайтом.
5. **Правки движка — в его репозиторий**, сюда только подъём тега (ADR-0011 в white-label).

## 3. Что сделано

| часть | файл | проверка |
|---|---|---|
| установка движка с тега v0.1.4 | `pyproject.toml` | `uv sync` ставит `yaseo==0.1.4` |
| бесплатный аудит в отдельном процессе | `src/yaseo_app/free_audit.py` | 7 тестов |
| тестовый сайт с заведомыми дефектами | `tests/site/` | битая ссылка, два h1, нет description |
| словарь находок простым языком | `src/yaseo_app/glossary.py` | 25 кодов техаудита и 22 кода готовности к ИИ, тест сверяет с исходниками движка |
| оценка сайта: число, три светофора, шаги | `src/yaseo_app/score.py` | 8 тестов |

Оценка считается так: критическая находка весит 10, серьёзная 3, мелкая 1. Техника —
штраф делится на число страниц, 10 на страницу означает ноль. Нейросети — штраф на сайт,
25 означает ноль. Зелёный от 80, жёлтый от 50. Светофор Яндекса в бесплатной проверке
серый и в общее число не входит. Шаги «что сделать первым» — группы одинаковых находок,
сначала критические, внутри — по суммарному весу.

Проверка на тестовом сайте: техника 0 (одна критическая, семь серьёзных, десять мелких на
трёх страницах), нейросети 56, общая 24. Первый шаг — «Ссылка в никуда», 5 минут.

```bash
uv run python -m unittest discover -s tests -v
```

## 5. Доработки движка, которые понадобятся

- Wordstat: динамика и распределение по регионам.
- Связка «YandexGPT + Web Search» как поставщик ответов (0,5–1,1 ₽ против 5,08 ₽).
- Точка учёта расхода: вызов функции после каждого платного обращения.
- Путь к базе и ключи параметром через весь стек.

Первые две нужны для отчёта, вторые две упрощают сервис, но обходятся изоляцией процессов.
