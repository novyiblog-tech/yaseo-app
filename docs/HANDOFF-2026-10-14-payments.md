# Handoff: оплата yaSEO через Т-Банк

**Дата:** 14.10.2026. **Код:** `main`, `033d23d` (выложен на yaseo.site). Заменяет точку подхвата из `HANDOFF-2026-10-02-payments.md` (тот файл не правим). Секреты (ключи, пароли терминалов) в Git и сюда не кладутся.

## Решения
- Провайдер: **Т-Банк, интернет-эквайринг**. Платёжная форма **банка** (не PCI, наш сайт карту не видит): Init → редирект на `PaymentURL` → GetState. Способы оплаты (карта, СБП, T-Pay) включаются в кабинете банка, код не меняется.
- Получатель денег: **ИП Цюрюмов Александр Александрович**, УСН «доходы», без НДС. Реквизиты оферты лежат только в `/etc/yaseo/app.env` на сервере (в публичном репозитории их нет); оферта на сайте уже без «Черновика».
- Чек по 54-ФЗ: нужен (услуга физлицам). Позиция «услуга», `full_payment` (доступ сразу), `usn_income`, `Tax=none`.

## Что сделано в коде
- `billing.TBankProvider` (Init, GetState, подпись SHA-256, сверка суммы). Адрес банка `securepay.tinkoff.ru/v2`, сертификат в корне Минцифры: путь к нему в `YASEO_TBANK_CA` (на сервере лежит `/etc/yaseo/ru-ca.pem`, сейчас в env не прописан).
- Возврат: статус `refunded`, `payments.refunded_at`, закрытие тарифа; продление отнимает только свой срок. Банк сообщает через webhook или при заходе на `/billing/return`. Из нашего кода возврат не запускается (метод Cancel не используется).
- `/pay/webhook/tbank`: берёт `PaymentId`, статус спрашивает у банка (телу не верим), отвечает `OK`.
- Режим `YASEO_PAYMENTS=off` (`OffProvider`): покупка отказывает до создания платежа. На боевом сервере стоит **off**: `fake` выдавал тариф даром (13.10.2026 Александр так «купил» два тарифа; аккаунт и платежи удалены по просьбе Сергея).
- Тесты: `tests/test_billing.py` (30), `tests/test_tbank.py` (3). Запуск: `uv run --locked python -m unittest discover -s tests -p 'test_*.py'`.
- Локально: `.claude/launch.json` → `web-tbank` (порт 8012) читает `.env.tbank` (в `.gitignore`, ключи тестового терминала).

## Что проверено на тестовом терминале (…DEMO)
- Успешная оплата, отказ (карта 5000…0009), возврат: у банка `CONFIRMED` / `REJECTED` / `REFUNDED`, у нас `succeeded` / `canceled` / `refunded`.
- Полный путь через сайт (кабинет → оплата → возврат на `/billing/return`) прошёл локально; на yaseo.site — покупка и срабатывание обработчика webhook на ручном запросе.
- **Не проверено:** уведомление **от банка**. На тестовом терминале адрес не настроен (в кабинете он включён только на рабочем). Чек и касса не проверялись: на тестовом терминале кассы нет.

## Что блокирует боевую оплату
1. Касса к рабочему терминалу не подключена (условия и стоимость банк не называл). После подключения платёж без `Receipt` не пройдёт; чек должен уйти покупателю на почту, это нужно увидеть на первом боевом платеже.
2. Ключ и пароль рабочего терминала (`1791800623273`) на сервер не внесены. Пароль светился на скриншотах в чате: при сомнениях перевыпустить в кабинете.
3. На сервере `YASEO_PAYMENTS=off`. Включить `tbank` и провести один боевой платёж на минимальную сумму с возвратом — только по отдельному явному решению Сергея.
4. Бухгалтеру Александра: `full_payment` против предоплаты для подписки; чек возврата; чек для плательщиков-организаций.

## Не сделано
- Автопродление: Recurrent/RebillId, повторное списание (`TBankProvider.charge` не реализован). `set_auto_renew` требует `payment_method`, который сейчас не сохраняется.
- Webhook-подпись банка не проверяем (статус всегда запрашиваем сами); при желании добавить проверку Token уведомления.
- Тесты с чеком (`Receipt`) и сценарием «отказ при частичном возврате».

## Порядок включения боя
1. Подключить кассу в кабинете. 2. Положить ключ и пароль рабочего терминала в `/etc/yaseo/app.env` (`YASEO_TBANK_TERMINAL`, `YASEO_TBANK_PASSWORD`), добавить `YASEO_TBANK_CA=/etc/yaseo/ru-ca.pem`. 3. `YASEO_PAYMENTS=tbank`, перезапуск `yaseo-web`, `yaseo-scheduler`, `yaseo-worker`. 4. Платёж на минимальную сумму, затем возврат из «Операций». 5. Проверить: webhook в логах, чек у покупателя, статусы у нас, оферта полная.
