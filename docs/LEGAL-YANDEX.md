## 2. Вывод

**Прямого запрета продавать собственный продукт, построенный на Search API, нет.**
Разрешённая цель сформулирована как «использование в продукте Клиента». Запрещены две вещи:
клон поисковика и подмена поиска в браузере — к нам не относятся.

Что говорит текст:

- Search API, п. 3.2: «Направлять Запросы и использовать результаты поиска разрешается в целях
  их использования в продукте Клиента. Размещение результатов поиска допускается в любом
  оформлении (дизайне), однако изменять порядок следования результатов поиска запрещается».
- Search API, п. 3.3.1: запрещено использование «в целях создания аналогичного продукта
  поисковой системы».
- Search API, п. 3.5: автоматические запросы к поиску любым другим способом запрещены без
  согласия Яндекса. То же в Лицензии, п. 6.6. Значит, парсинг выдачи мимо API — нарушение,
  а API — единственный законный путь.
- Оферта, п. 10.6: «Яндекс не несет ответственности по претензиям и искам третьих лиц, в случае
  если Клиент оказывает услуги таким третьим лицам с использованием Сервисов» — оказание услуг
  третьим лицам договором предусмотрено.
- Foundation Models, п. 3.15: запрещена «перепродажа Сервиса третьим лицам через простой вызов
  функций API», но запрет «не распространяется на случаи, когда Сервис используется для
  доработки и развития собственного продукта Клиента и дальнейшей продажи такого продукта».
  Это условия соседнего сервиса, в условиях Search API такого пункта нет; показывает, где
  Яндекс проводит границу.

## 3. Что из этого следует для продукта

| требование | откуда | что делаем |
|---|---|---|
| Не быть прокси к API | дух п. 3.2, аналогия с FM 3.15 | продаём отчёт, оценку, рекомендации, наблюдение. Сырых выгрузок «запрос → выдача» по произвольным запросам и своего API к данным Яндекса не даём |
| Порядок результатов не менять | Search API 3.2 | позиции и топ конкурентов показываем в порядке Яндекса. Сортировки и фильтры — отдельным видом, с подписью, что порядок изменён |
| Не упоминать Яндекс как партнёра | Оферта 13.7: упоминания о Яндексе и факте сотрудничества — только с письменного согласия | на лендинге и в отчёте без логотипов Яндекса и слов «партнёр», «официальные данные». Нейтрально: «позиции в поиске Яндекса» |
| Генеративный текст не выдавать за человеческий | FM 3.11.4, 3.11.5 | раздел «Нейросети» и рекомендации, написанные моделью, помечаем |
| Один договор — один клиент | Оферта 7.4.12 | ключ и каталог Облака оформляются на то же лицо, которое принимает деньги (ИП) |
| Потолки Яндекса | Search API 3.6 | 1 млн пользователей в день и 100 млн запросов в месяц — нам не грозит |

## 4. Квоты (важнее, чем казалось)

| ограничение | значение |
|---|---|
| синхронные запросы | 10 в секунду, 10 000 в час |
| отложенные запросы | 10 в секунду, 35 000 в час |
| генеративный ответ | 1 в секунду, 1 000 в час |
| **Wordstat** | 10 в секунду, **100 в час** |
| результатов в ответе | не более 250 |
| длина запроса | 400 символов, 40 слов |
| отложенный запрос | обработка от 5 минут, результат хранится 12 часов |
| генеративный ответ | до 5 сайтов, 5 хостов, 10 страниц в запросе |
| Wordstat | до 20 ассоциаций |

Квоты (не лимиты) поднимаются заявкой в поддержку.

**Узкое место — Wordstat, 100 запросов в час.** Полный аудит по плану берёт 65 запросов
Wordstat: на стандартной квоте это один полный аудит в час на весь сервис. Решения:
заявка на подъём квоты до запуска; общая очередь Wordstat с расчётом времени готовности;
кэш (сейчас в плане 24 часа, для Wordstat можно 7–30 дней — статистика месячная);
экспресс-проверка — не больше 5 запросов Wordstat.

Результат отложенного запроса надо забрать за 12 часов, иначе запрос оплачен впустую.

## 4б. Вебмастер и Метрика (сверено 30.09.2026)

Сергей: «проверь цены конкурентов и условия Вебмастера с Метрикой».

### API Вебмастера — условия жёсткие, редакция 18.12.2014

Документ: yandex.ru/legal/webmaster_api. API бесплатный, доступ — по согласию владельца сайта
через OAuth (п. 2.3).

| пункт | что сказано | что значит для yaSEO |
|---|---|---|
| 2.8 | нельзя «сохранять, обрабатывать, систематизировать, передавать третьим лицам и видоизменять Данные» | историю из Вебмастера у себя не копим, в общую оценку и прогноз не подмешиваем. Данные запрашиваем в момент показа |
| 2.4 | данные показываются только владельцу сайта, к которому они относятся | агентству чужой сайт показываем, только если OAuth дал сам владелец |
| 2.7 | рядом с данными обязателен логотип Яндекса и текст «Данные предоставлены сервисом Яндекс.Вебмастер» со ссылкой | раздел Вебмастера в отчёте — отдельный блок с этой подписью |
| 2.6 | сервис должен быть открыт неограниченному кругу лиц, регистрация ограничением не считается | закрытая бета по приглашениям под вопросом |
| 2.1 | пользователем назван владелец хостинга или разработчик программ для таких ресурсов | формулировка 2014 года, SEO-сервис в неё прямо не попадает |
| 4.2 | приложение OAuth нельзя регистрировать для третьих лиц и передавать | приложение регистрирует то же лицо, что владеет продуктом |
| 5.1 | доступ могут закрыть без объяснения причин | отчёт должен собираться и без Вебмастера |

Вывод: Вебмастер подключаем как **живую витрину** — блок «данные вашего Вебмастера» в кабинете
с подписью Яндекса, без хранения и без участия в расчётах. В PDF — под вопросом: PDF это
сохранение. Квоты запросов в документации числом не названы, есть только ошибки
`QUOTA_EXCEEDED` и `TOO_MANY_REQUESTS_ERROR`; число не проверено.

Противоречие с 13.7 оферты Облака (Яндекс не упоминать) кажущееся: там речь о сотрудничестве
по договору Облака, здесь подпись требует сам Яндекс и только у данных Вебмастера.

### API Метрики — условия мягче, редакция 07.08.2026

Отдельных условий API нет (адрес из поисковой выдачи yandex.ru/legal/metrica_api отдаёт 404),
действует общее соглашение yandex.ru/legal/metrica_termsofuse.

- п. 2.4: владелец счётчика вправе дать третьим лицам доступ к данным штатными средствами
  и отвечает за их действия. Наш путь: OAuth от владельца или гостевой доступ к счётчику.
- п. 2.3: логин, пароль и API-ключ передавать нельзя — значит, только OAuth, токенов
  «вставьте сюда» не просим.
- Запрета хранить и обрабатывать полученную статистику, как у Вебмастера, в соглашении нет.
- п. 5.4: оператор персональных данных посетителей — владелец сайта. Берём только
  агрегаты (визиты из поиска, цели), Logs API с сырыми визитами не трогаем.

Квоты (yandex.ru/dev/metrika/ru/intro/quotas):

| ограничение | значение |
|---|---|
| запросов с одного IP | 30 в секунду, Logs API — 10 |
| параллельных запросов на пользователя | 3 |
| запросов на пользователя в сутки | 5 000 |
| запросов к API отчётов | 200 за 5 минут |

Квоты считаются на логин владельца, а IP у нас общий: 30 в секунду — потолок всего сервиса.

## 5. Открытые риски

1. **Имя yaSEO.** «Ya» читается как Яндекс (ya.ru). Товарные знаки Яндекса и п. 13.7 оферты
   дают повод для претензии к имени платного продукта. Не проверено: поиск по реестру
   Роспатента, 9/35/42 классы. До покупки домена и вёрстки лендинга — проверить.
2. **Письменное подтверждение.** Текст условий допускает наш сценарий, но формулировка
   «продукт Клиента» общая. Вопрос в поддержку Yandex Cloud: «платный SaaS с SEO-отчётами
   для третьих лиц на данных Search API и Wordstat — допустимо?» Ответ сохранить.
3. **Условия меняются.** У Search API три редакции за 13 месяцев (15.08.2025, 09.08.2026,
   07.09.2026). Нужна проверка редакции раз в месяц.
4. **Хранение.** Срока хранения результатов условия не задают. Историю позиций хранить можно;
   архив выдачи, доступный клиенту как база, — уже похоже на п. 3.3.1.
